Phase 1 The Employee Experience (Self-Marking)
1
Template Generation

The script reads the employee's Designation, queries the KRASetup form, and pulls their specific role requirements. It loops through these templates to generate brand new, empty rows in the subform.

setupRecord.KRA.insert()
2
UI Lockdown

The system secures the definitions. It ensures the employee cannot accidentally or intentionally alter their official job requirements or the weightages assigned to them by HR.

disable KRA.KRA_Name
3
Role Isolation

The script hides the manager grading column entirely. The employee is presented only with the fields relevant to their self-assessment, keeping the interface clean and preventing confusion.

hide KRA.Actual_Mark
4
Live Calculation

As the employee inputs their scores, an 'On User Input' script specifically targets the self-mark column, sums the values, and pushes the aggregate score to the Total field at the bottom.

input.Total = self_total
Phase 2 The Manager Experience (Reviewing)
1
The Prerequisite Check

Before revealing any form fields, the script searches the database for the employee's self-appraisal. If no record is found for the selected quarter, the manager is blocked from proceeding.

existingRecord.count() > 0
2
Double-Grade Prevention

The script scans the existing record to see if the Manager's Actual Mark column is already populated. If it is, the system halts the process to prevent overwriting historical reviews.

checkRow.Actual_Mark != null
3
Data Fetching

Once cleared, the script pulls the employee's saved record, creates a new row for every KRA, and explicitly copies the employee's Self-Marks into the manager's current view for reference.

newSubformRow.Self_Mark = row.Self_Mark
4
The UI Switch

The employee's self-marks are locked as read-only. The manager's actual mark column is revealed. The Total formula shifts its logic to sum only the manager's final inputs.

show KRA.Actual_Mark
